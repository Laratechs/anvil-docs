# anvil-docs: guidance for agents

The GitHub Pages site documenting Anvil. Read [README.md](README.md) first:
it explains the three layers (content, structure, theme) and how docs
arrive from Laratechs/anvil.

## Rules

- **Never edit `upstream/`** except through `scripts/sync-upstream.mjs`.
  It mirrors another repository verbatim. To change those words, change
  them in that repository (the Anvil checkout is usually at `../anvil`).
- **Never commit `src/content/docs/upstream/`.** It's generated by
  `npm run content` (part of `dev` and `build`).
- **Structure lives in `site.structure.mjs` only.** The sidebar, the home
  page's persona cards and the generated pages all read it. Don't hardcode
  navigation anywhere else.
- **Look lives in `theme/` only.** No colours, font names or sizes in
  content pages or outside `theme/tokens.css`; follow
  [theme/README.md](theme/README.md).
- **Authored pages orient; upstream pages explain.** A persona overview
  says what the reader can do and links to the page that explains it. Don't
  copy facts from upstream docs into authored pages beyond a short
  example, because copies drift.
- Write for the persona of the section the page is in: engineers using
  Anvil (`use/`), platform engineers running it (`run/`), catalog authors
  (`catalogs/`). Use the terms in the glossary (Anvil's `CONTEXT.md`).
- Dependencies and GitHub Actions are pinned to exact versions (actions by
  commit SHA, with the version in a comment). Keep them pinned when
  updating.

## Checking a change

`npm run build` must pass: it fails on a missing upstream file or heading,
or an authored page listed in the structure that doesn't exist. For a
visual or navigation change, run `npm run dev` and look at the page in both
dark and light themes and at phone width.

**Stop every server you start before you finish.** That covers
`npm run dev`, `npm run preview` and anything else that runs `astro`.
Stop each one the same way you started it: preview_stop for a preview
server, or kill the background shell's process. Then check that nothing is
still listening, for example with `pgrep -fl astro` or `lsof -i :4321`.
A server left behind holds the port, so the next one starts on a different
port and you end up checking a stale build.
