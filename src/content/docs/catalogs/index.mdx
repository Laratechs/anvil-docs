---
title: Build a catalog
description: For catalog authors who define what Anvil's services and clouds are made of.
---

import { LinkCard, CardGrid, FileTree } from '@astrojs/starlight/components';

Anvil's engine doesn't know what a service or a cloud is made of. A
**catalog** does: its definitions name the Terraform modules a service and
each cloud are built from, the settings, bindings and options they accept,
and what they report back. The [catalog contract](contract/) is the only
interface between the two, versioned and checked when the server loads the
catalog.

A catalog is a directory, or the root of a Git repository:

<FileTree>
- catalog.hcl the catalog block: contract version and requirements
- definitions/
  - service.hcl exactly one service block
  - cloud-gcp.hcl any number of cloud blocks
- components/ optional local Terraform modules
  - run/
    - main.tf
    - anvil.json optional component manifest
</FileTree>

Platform engineers run a catalog by pinning it in the server's
configuration, for example
`catalog { source = "git::https://github.com/<org>/<catalog>.git?ref=v1.0.0" }`.
The reference catalog is
[Laratechs/anvil-catalog](https://github.com/Laratechs/anvil-catalog).
